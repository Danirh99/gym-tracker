# Modelo Entidad/Relación

## Objetivo del modelo

El modelo debe permitir registrar entrenamientos personales de forma flexible, diferenciando entre ejercicios de fuerza, cardio, abdomen u otros tipos.

El sistema se centra en esta relación principal:

```txt
Una sesión tiene varios ejercicios registrados.
Cada ejercicio registrado puede tener uno o varios detalles.
```

---

# Entidades principales

## Exercise

Representa un ejercicio, máquina o actividad.

Ejemplos:

```txt
Press pecho máquina
Cinta
Elíptica
Plancha abdominal
Sentadilla
Remo sentado
```

Campos:

```txt
id
name
type
muscle_groups
notes
is_active
created_at
updated_at
```

Valores internos del campo `type` y su etiqueta en la UI:

```txt
strength -> Fuerza
cardio   -> Cardio
core     -> Abdomen
other    -> Otro
```

---

## WorkoutSession

Representa una sesión completa de entrenamiento.

Ejemplo:

```txt
Pecho + cardio suave
Viernes 22 de mayo
Sensación: buena
```

Campos:

```txt
id
name
session_date
mood
notes
started_at
finished_at
created_at
updated_at
```

---

## WorkoutEntry

Representa un ejercicio concreto realizado dentro de una sesión.

Ejemplo:

```txt
En la sesión del viernes hice Press pecho máquina.
```

Campos:

```txt
id
workout_session_id
exercise_id
order_index
notes
created_at
updated_at
```

---

## WorkoutSet

Representa los datos concretos del ejercicio realizado.

Los campos numéricos son opcionales y se rellenan según el tipo de ejercicio.
En fuerza suelen usarse `weight_kg` y `reps`; en cardio, `duration_seconds`, `distance_meters` y métricas asociadas; en abdomen u otros ejercicios, sobre todo `duration_seconds` y `notes`.

Para fuerza puede ser una serie:

```txt
40 kg - 12 repeticiones
```

Para cardio puede ser un bloque:

```txt
25 minutos - 2.8 km
```

Campos:

```txt
id
workout_entry_id
set_number
weight_kg
reps
duration_seconds
distance_meters
speed_kmh
incline
resistance_level
calories
notes
created_at
updated_at
```

# Relaciones


# Explicación del diseño

## Por qué separar Exercise de WorkoutEntry

**Exercise** es el catálogo.

Ejemplo:

```txt
Press pecho máquina
```

**WorkoutEntry** es el uso de ese ejercicio en una sesión concreta.

Ejemplo:

```txt
Press pecho máquina dentro del entrenamiento del lunes
```

Esto permite consultar el historial de un ejercicio sin duplicar datos.

---

## Por qué usar WorkoutSet para todo

Aunque se llame `WorkoutSet`, también sirve para cardio.

En fuerza representa una serie.

En cardio representa un bloque de actividad.

Ejemplos:

```txt
Fuerza:
Serie 1: 40 kg - 12 reps

Cardio:
Bloque 1: 25 min - 2.8 km

Abdomen:
Serie 1: 45 segundos
```

Esto simplifica el modelo y evita crear tablas distintas para cada tipo de ejercicio.

# Estado para registro por tipo

El modelo actual esta preparado para soportar las pantallas separadas de Fuerza, Cardio y Abdomen/Otros sin cambiar tablas.

Motivos:

```txt
- Exercise.type define el tipo de formulario a mostrar.
- WorkoutEntry enlaza sesion + ejercicio y mantiene orden.
- WorkoutSet ya incluye metricas de fuerza, cardio y notas libres.
```

Puntos a vigilar en la capa de API/validacion (no en el ER):

```txt
Fuerza:
- Requerir al menos weight_kg o reps por serie.

Cardio:
- Requerir al menos duration_seconds o distance_meters por bloque.

Abdomen/Otros:
- Permitir reps o duration_seconds, con notes opcional.
```

Recomendacion opcional para robustez futura:

```txt
- Guardar un snapshot del type en WorkoutEntry para proteger historicos
  si el ejercicio del catalogo cambia de tipo en el futuro.
```
